# 个人发票管理与月度报销

本地管理 PDF 发票，分“餐补”和“其他”两类，并按购买方公司分别办理报销。餐补按“实际天数 × 每日标准”自动凑票，其他发票手动勾选，合并成一张月度报销单。每日标准默认 25 元。

## Windows 使用

在 GitHub **Actions → Build Windows EXE** 下载最新成功构建的 **InvoiceManager-Windows-x64**，解压后运行 `InvoiceManager.exe`。支持 Windows 10/11 64 位，无需安装 Python 或 SumatraPDF；批量打印使用 Microsoft Edge。

程序在 EXE 旁的 `data/` 保存库存和原件。请放在可写目录中，更新时关闭程序，只替换 EXE，保留 `data/`。首次启动单文件程序需要解压运行库，请稍候。

源码运行：

```powershell
py -m pip install -r requirements.txt
py app.py
```

自行打包需要 Windows 和包含 Tcl/Tk 的 Python：

```powershell
py tools/build_windows.py
```

也可以双击 `build_windows.bat`。构建脚本会建立独立环境、验证 EXE，成功后输出 `dist/InvoiceManager.exe`。若旧 EXE 正在运行无法替换，新版本保存为带时间和编号的文件，脚本会打印实际路径；它使用同目录下的 `data/`。

## 导入与库存

“发票库存”提供“导入餐补”“导入其他”，支持多选 PDF；“扫描文件夹”可按分类批量导入文件夹中的 PDF。

- 自动识别发票号、日期、购买方、销售方和价税合计，按发票身份去重，改名后重复导入也不会新增。
- 支持 20 位数电发票，以及“发票代码＋8 位号码”的传统电子发票。
- 成功导入时复制原始 PDF 到 `managed_pdfs/`，不修改原文件。重复导入不改变原有分类、备注、打印和使用状态。
- 库存支持搜索、购买方、分类及状态筛选；可批量设置已打印或未打印。双击发票行修改备注，选中单张可打开原件。
- 可将待使用发票移至餐补或其他分类；已预留、已使用或关联有效报销单的发票不可调整分类或删除。
- 删除记录需弹窗确认，只删除数据库记录，保留原始 PDF。

### 扫描目录自动同步

选择一次扫描目录后会记住位置；餐补、其他各可设置一个目录。库存页可勾选“自动同步扫描目录”，也可以在“同步目录设置”中查看、更换或移除目录。同一目录最后一次选择的分类生效，已入库发票分类不因同步而改变。

- 程序运行期间每 10 秒检查一次该目录内的 PDF，不递归扫描子目录。文件连续两次检查大小和修改时间都稳定后才导入，通常在稳定后约 10～20 秒发现。
- 新增或修改过的文件按设置的分类自动导入，按发票身份去重；不改变既有原件、备注、打印和使用状态。
- 程序关闭期间不运行后台服务，重启后补查未处理文件；开关、目录及处理记录会保存。
- 自动同步不清空当前搜索或筛选。同步结果显示新增、重复和失败数量；失败沿用详情窗口，可复制原因并重试。
- 同一份未变化的失败文件不会每 10 秒重复弹窗，可在详情中重试，或手动重新扫描；文件修改后会再次检查。
- 删除源文件不会删除库存。手动删除库存后，未变化的源文件不会在重启时自动重新入库；手动扫描或重新导入仍可主动恢复。
- 目录不可访问时显示原因，恢复后继续检查。暂停后不启动下一批同步，已经开始的导入会完成。

从旧版本更新后，需要重新选择一次扫描目录，才会加入自动同步。

### 导入失败看原因

底部汇总新增、重复和失败数量。**只要存在失败，会自动打开处理详情窗口**，逐文件显示结果、完整路径和原因。

例如：PDF 需要密码、未提取到文字需 OCR、未识别到价税合计、文件不存在或没有访问权限。未知错误保留实际错误类型与信息，便于排查，不统一归为“格式错误”。一张失败不影响其他文件继续导入，重复单独统计。

详情窗口可复制失败明细、重试仍然存在的失败文件；关闭后可点击“查看本次处理详情”重新打开。重试沿用原分类，不重新导入已成功的文件。

## 报销只需两步

### 1. 准备报销

选择购买方公司，填写月份 `YYYY-MM`、实际可报销天数和每日标准，需要时展开“选择其他发票”勾选。月份默认上个月；2025、2026 年的天数按国家放假调休安排自动填入，仍可手动修改。也可填写“直接输入报销金额”，覆盖天数 × 每日标准计算出的餐补目标。只报其他发票时，天数填 0。一张报销单不会混用不同购买方公司的发票。

后续年份的国务院放假安排公布后，可在数据目录中新建 `holiday-schedules.json`。源码运行时数据目录是项目根目录，EXE 运行时是 EXE 同级的 `data/`。文件按年份填写放假起止日与调休上班的周末，例如以下内容仅展示格式，**不是 2027 年官方安排**：

```json
{
  "2027": {
    "holidays": [["01-01", "01-03"]],
    "work_weekends": ["01-09"]
  }
}
```

程序会校验日期，并在选择该年份的月份时自动填入工作日；没有配置的年份仍需手动填写。

点击 **“生成报销单”**，程序自动凑票并预留，直接显示本单张数、应报销额、实际金额和差额。无需再确认方案。创建失败不占库存，重复点击不重复建单。

生成后隐藏输入表单，避免与当前单据混淆。每日标准在成功生成后保存，下次启动沿用。

### 2. 办理报销

本单可直接：

- **打印 PDF**：打开原始尺寸的合并 PDF。
- **导出到文件夹**：将所勾选的原始发票复制到指定目录。
- **完成报销**：实际报销完成后点击，弹窗核对月份、整单张数及金额，确认才标记整单已使用。

打印、导出、完成报销相互独立，不要求先打印或导出。复选框只控制输出范围，不改变整张报销单的组成。

进入报销单时，默认只勾选未打印发票；需要重新打印时可手动勾选已打印发票。

完成后自动清空当前明细和选择，月份回到上个月并重新计算工作日天数，保留每日标准，回到准备报销页面。库存、历史同步刷新；保存失败则保留当前页面并弹窗说明原因。

“取消此报销单”弹窗确认后删除本单和明细、释放预留，自动复位，原件、备注和打印状态保留。取消确认弹窗或选择“否”不改变状态。

每张发票只能整张使用一次，不拆分，不保留剩余额度。已使用发票不能恢复待使用。

## 打印保留原始排版与尺寸

程序直接复制原 PDF 页面进行合并：保留原始页面尺寸、方向、文字、线条、颜色和注释；不转图片、不改成 A5、不加边距、不缩放或裁切。多页原票保留所有页，不同尺寸的发票各自保留原尺寸。

Windows 使用 Edge 打开合并文件。按 **Ctrl+P**，选择 **“实际大小 / 100%”**，纸张、方向及黑白按实际需要设置，并核对预览。纸张小于原始页面时可能裁切，请选择合适纸张。程序不自动设置 Edge 的打印选项。

成功打开或提交打印 PDF 后，程序会自动弹出打印结果确认框，无需再点击其他按钮。请先完成实际打印，再选择 **“是”**；程序只将本次提交的发票标记为已打印，不受后来勾选变化影响。选择“否”、关闭弹窗或打印失败时，打印状态不变。

Windows 副本保留在系统临时目录 `invoice-print-*` 中，避免 Edge 异步读取时被删除；关闭 Edge 后可通过系统临时文件清理删除。Linux/macOS 使用 CUPS `lp`，设置不缩放；实际纸张与驱动仍需用户核对。

云环境仅验证文件和交互逻辑，没有实体打印机验证。

## 导出到指定文件夹

首次点击“导出到文件夹”时选择根目录，例如：

```text
E:\Workspace\TOOLS\Invoice\已报销
```

程序记住位置，之后直接使用；需要时点击“更改导出目录”。自动创建本次文件夹：

```text
已报销\
└─ 2026-11应报销：900实际报销：899差额-1\
   ├─ 发票号_销售方名称_金额.pdf
   └─ …
```

- 默认全选整单，可只导出勾选部分。
- 应报销额取整单目标，实际金额取本次勾选发票合计，差额为实际减应报销。
- 使用 Windows 支持的全角冒号 `：`，金额去掉多余末尾零；销售方名称中的非法文件名字符替换为下划线。
- 复制原始 PDF 字节，不使用打印合并件，不压缩为 ZIP。
- 同名目录已存在时添加 ` (2)`、` (3)`，不覆盖已有输出。
- 原件缺失或复制失败会弹窗说明原因，移除本次未完成的输出，不提示成功。
- 完成后可点击“打开导出文件夹”。导出不修改打印或报销状态。

## 报销历史

“报销历史”中选中待报销单据，可继续打印、导出或完成。关闭程序不会释放预留，重启后仍可继续。

已完成单据在独立查看窗口打开，可查看、重打和导出，不能再次报销或取消，也不会覆盖正在办理的新单。当前已有待办单据时，需先完成或取消，再打开另一张待办。

## 数据与备份

关闭程序后备份整个数据目录，至少包含 `invoices.db` 和 `managed_pdfs/`；旧发票仍位于 `invoices/` 时也要一起复制。`settings.json` 保存导出根目录、每日标准及同步设置，`folder-sync.json` 保存已处理文件的大小与修改时间；可一起备份。

源码版默认使用仓库根目录，EXE 版使用 EXE 同级 `data/`。也可以通过 `INVOICE_MANAGER_DATA_DIR` 指定独立目录。从源码迁移到 EXE 时，关闭程序并将数据库、原件和设置复制到 `data/`，勿覆盖另一份正在使用的数据。

虚拟环境、缓存、`build/`、`dist/` 可重建；数据目录和发票原件不能当缓存删除。历史已跟踪的数据库及示例发票保留，不打入 EXE。个人设置和保管副本已加入 Git 忽略。
